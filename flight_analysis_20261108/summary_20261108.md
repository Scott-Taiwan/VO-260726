## 今天診斷出的問題

1. **VO 幾乎沒追蹤到任何一趟的真實水平移動**——三張軌跡圖都呈現同一個模式:真實GPS畫出完整飛行路徑,VO估計卻卡在起點附近一小團打轉。主因是相機凍結/卡幀。
2. **CSI/Argus 相機硬體間歇性不穩定**——I2C probe 間歇性失敗(`-121` EREMOTEIO)、反覆開關相機造成 CMA 記憶體耗盡(`NvMapMemAllocInternalTagged ... error 12`)。今天在機器上直接用 `gst-launch-1.0` 實測,連續測試時也真的重現了「CaptureSession 建立失敗」,重啟 `nvargus-daemon` 後才恢復穩定。
3. **相機曝光原本是全自動**,預設曝光時間接近 1/30s(~33ms),飛行/晃動時嚴重動態模糊,拖累 SIFT 特徵匹配品質。
4. **高度計算的 NaN / 暴衝 bug**——`_displacement_from_transform()` 裡 `altitude_m*(1/scale-1)` 在 `scale` 退化(接近0)時會產生 `nan` 或誇張的大數字,透過 `PositionTracker.alt_m +=` 累加後永久汙染整趟飛行後續的高度估計。已在第三趟飛行的真實資料裡找到實際案例(82.13m 的異常高度讀數附近)。
5. **絕對高度(alt_msl)不可跨飛行/session比較**——同一個地點,三趟的起飛錨點高度分別讀到 14.7m / 17.3m / 42.2m,差異來自 GPS 垂直精度差(無RTK修正)+氣壓計隨時間飄移,`relative_alt`(AGL)每次解鎖都是重新歸零,不代表三趟高度基準一致。
6. **低空(~14.5m)懸停時晃動被放大**——同樣幅度的機身晃動,離地面越近在畫面上佔的像素比例越大(GSD小),加上草地本身紋理重複,造成 inliers 持續不足。
7. **`MIN_INLIERS` 門檻導致連續失敗腿時,VO 的 lat/lon/高度會整段一起凍結**,直到重新抓到足夠的 inliers 才恢復更新——這是設計上刻意保守的行為,不是 bug,但代表資料中會有「停滯空窗期」跟不上真實飛行。

## 今天完成的修復與新工具

1. **相機曝光/快門調整**:`config.py` 新增 `EXPOSURE_TIME_RANGE_NS` / `GAIN_RANGE` / `ISP_DIGITAL_GAIN_RANGE`,套用進 `live_vo_gps.py` 的 `gstreamer_pipeline()`,三支飛行程式(`vo_flight_capture.py`/`_always.py`/`_1s.py`)開機時都會把目前套用的曝光參數印到終端機和 log。實測值依據是 `gst-launch-1.0`+`GST_DEBUG=3` 量到的 IMX219 真實硬體範圍(曝光 13,000–683,709,000 ns,增益 1.0–10.625x)。
2. **新增 `test_camera_shot.py`**:不用起飛,地面搖晃相機就能存一張測試照,檔名會自動帶入當下的曝光/增益設定,方便比較不同參數的效果。
3. **修復高度 NaN / 暴衝 bug**:`config.py` 新增 `SCALE_SANE_RANGE = (0.3, 3.0)`;`vo_flight_capture.py` 和 `visual_odometry.py` 的位移計算函式在 `scale` 超出這個範圍時改回傳 `0.0`(不再更新高度),不再是 `nan` 或誇張數字;`dead_reckoning.py` 的 `PositionTracker.apply_leg()` 另外加了 `math.isfinite()` 防護,作為所有呼叫者共用的最後一道防線。已用退化 transform(`scale=0`)實測驗證修復有效。
4. **三趟飛行的軌跡分析**:重複利用 `parse_flight_results.py` 產出完整的真實vsVO軌跡圖與CSV,另外針對第二趟的「比較好的平移」時段、第一趟的懸停時段各別做了放大分析圖。
5. **產出 filename↔log line 對照 CSV**(`*_filename_logline_map.csv`,每趟一份):順便發現三趟的 log 檔都在中途斷線(終端機/tee連線中斷),但實際拍攝沒有受影響,仍持續拍到飛行結束。

## 建議

1. **飛行前先確認相機能穩定開啟**:`gst-launch-1.0 nvarguscamerasrc num-buffers=3 ! fakesink` 連測幾次,若失敗先 `sudo systemctl restart nvargus-daemon` 再試,不行可能要重開機。
2. **曝光 1–5ms / 增益 1.0–10.625x 只是起始值**,建議戶外用 `test_camera_shot.py` 實際拍幾張,依亮度/拖影程度微調 `config.py` 裡的數值。
3. **飛行/懸停高度建議至少 25–30m 以上**,避免低空晃動放大效應;實際資料蒐集建議維持在 40–70m 範圍(今天第二、三趟大致落在這個區間)。
4. **建議之後安排一次高度斜坡測試**(例如 10m/20m/40m/60m 各懸停~20秒),直接比較不同高度下的 match/inlier 品質,找出這套設備+當天風況下實際的臨界高度。
5. **CSI 相機 slot 9 vs 10 的穩定性比較還需要更多開機樣本**,建議持續用 `journalctl -b 0 | grep imx219` 記錄每次開機的結果。
6. **絕對高度(alt_msl)不要跨飛行比較**,只能看同一趟飛行「內部」的相對變化;需要跨飛行比較高度時,應該用 AGL 或額外做一次地面校正。
7. **尚未處理的小尾巴**:`process_dji_sequence.py` 裡有同一個 scale/altitude NaN bug 的獨立副本(用於離線 DJI 測試資料分析),因為是離線用途、風險較低,今天沒有一併修,有需要再說一聲。
